About PDF Lens

A small static analysis workbench. PDF bytes stay in your browser; scripts, links and attachments are treated as data.

What this version supports

Dedicated script and attachment lists with declared trigger contexts and clickable reference paths, objects and compressed object streams, evidence highlights, raw/hex views, and Flate, LZW, ASCIIHex, ASCII85 and RunLength stream filters. PNG and TIFF predictors are supported, including 1, 2, 4, 8 and 16-bit components. Scripts include syntax-based capability summaries, literal timer callbacks, possible function definitions and same-handle cancellation calls. The form-field inventory links declared fields, widgets, actions and scripts. Complete checksum-verified Flate members can be recovered when trailing bytes are present; original and trailing bytes remain exportable. URLs and email addresses are extracted with source context and source-category filters. A separate PDF.js engine recovers font-aware Unicode page text; page text is searchable, copyable and exportable.

Know the limits

This is a forensic object scan, not a full PDF validator. The forensic scan does not resolve cross-reference precedence, revision history or action reachability. Page text is extracted separately from the page tree selected by PDF.js. It does not decrypt encrypted PDFs, automatically inspect image pixels, run YARA, render PDF pages or execute JavaScript. Ordinary opening-view destinations are explained separately from action declarations. Routine image pixel/codec coverage is summarised outside investigation leads; detected structural anomalies and image decoding failures remain leads. The Image tab offers JPEG extraction and on-demand previews of eligible JPEGs or decoded DeviceGray, DeviceRGB and DeviceCMYK samples, including Indexed colour palettes. Attachment signatures are byte-based hints, not full file validation.

The default limits are 300 MB per PDF, 12 MB per stream and 300 MB of decoded data per document. Use Settings to adjust these limits, timeouts and other analysis budgets. PDF.js has its own text extraction settings. Direct and indirect stream lengths are checked against discovered boundaries; unresolved references and actual mismatches are distinguished. Incomplete decoding and parsing are reported.

Sessions are held in memory. Export a report before closing the tab. Extracted bytes are downloaded as .bin files.

Text extraction uses Mozilla PDF.js 5.6.205 (Apache License 2.0), with bundled CMaps and standard fonts. Acorn parses script syntax without execution; pako provides bounded zlib recovery. Keep pdf-engine.js and pdf-analysis-libs.js beside the HTML for offline use. Libraries fall back to jsDelivr when the local files are unavailable. Licence notices accompany the local libraries.
